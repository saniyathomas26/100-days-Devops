
# Day23 - Fork a repository
User: Jon

Project: Nautilus Development

Platform: Gitea Self-Hosted Git Service

## 📋 Overview
To begin contributing, Jon needs his own copy of the existing project. In Git workflows, this is called Forking. This allows Jon to make changes in his own space without affecting the original "upstream" code managed by Sarah.

## Step-by-Step Instructions
### 1 Access the Git Portal
Locate the Gitea UI button on the top navigation bar of your workstation.

Click the button to open the Gitea web interface in your browser.

### 2 Authentication
Log in with the following credentials provided by the DevOps team:

Username: jon

Password: Jon_pass123

### 3 Locate the Source Repository
Once on the dashboard, use the search bar or explore the repositories.

Find the repository owned by Sarah: sarah/story-blog.

### 4 Execute the Fork
Open the sarah/story-blog repository page.

In the top-right corner, click the Fork button.

Confirm that the destination user is jon.

Click Fork Repository.

## Success Verification
After the process finishes, you should see a new repository URL:

http://[git-server-ip]/jon/story-blog

Note: This repository is now Jon's personal copy. He has full "Write" access here and can safely push his experimental code or bug fixes.
